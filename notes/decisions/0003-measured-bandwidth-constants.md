# ADR 0003 · 预算模型的带宽常数用实测值而非规格书

- 状态：已接受
- 日期：2026-11-16
- 相关：`tools/budget_model.py` 顶部常数、`docs/BENCHMARKS.md`

## 背景

初版预算模型用的是"常见配置"的经验值：

```python
BW_PCIE_GBPS = 12.0   # Gen4 x16 的 37%
BW_HOST_GBPS = 45.0   # DDR5-5600 双通道
BW_VRAM_GBPS = 250.0
```

在本机实测后发现全部错得离谱：

| 常数 | 初版 | 实测 | 差 |
|---|---:|---:|---:|
| PCIe | 12.0 | 11.0（x8，不是 x16） | −8% |
| 主机内存 | 45.0 | **19.3**（单条，4800 不是 5600） | **−57%** |
| VRAM | 250 | 未测（无 torch） | 未知 |

## 决策

**所有常数改为本机实测值的保守估计，并在代码里写明来源与测量方法。**

```python
BW_PCIE_GBPS = 11.0     # Gen4 x8 的 15.75 理论值 × 70%
BW_HOST_GBPS = 17.0     # 实测 19.3 × 88%
BW_VRAM_GBPS = 280.0    # 448 理论峰值 × 62%（未实测，标注为经验值）
USABLE_VRAM_GIB = 7.0   # 实测空闲 7178 MiB 减 178 MiB 抖动
USABLE_RAM_GIB = 12.0   # 实测可见 15.19 GiB 减 OS 常驻
```

## 理由

1. **规格书在笔记本上普遍虚高 2 倍**。最典型的是内存：标称 16 GB / 5600 MT/s 双通道，实际 15.19 GiB 可见 / 4800 单条 / 19.3 GB/s。差了 57%。

2. **错误方向的偏差是致命的**。用 45 GB/s 会算出 P3 有 30+ tok/s，实际只有 9.4。这种乐观偏差会让所有设计决策建立在错误前提上。

3. **保守估计有成本，但是可控的**。用 17 而不是 19.3，P3 的估计慢 12%。相比之下，用 45 的估计快 130%，后者会导致完全错误的方案选择。

## 已知遗留

`BW_VRAM_GBPS = 280` **仍是经验值，不是实测**。本机没有 CUDA toolchain（见 `docs/05-risks.md` R2），无法测 GPU 带宽。

这是一个明确的债：装好 torch 后必须补测，并把 280 换成实测值。**在那之前，所有 tok/s 数字都是"基于 62% 效率假设"的估计。**

## 后果

- P1 的 51.1 tok/s 是估计，实际可能 30-40
- 阶段一 1.7 的端到端实测必须记录偏差
- 若偏差 > 30%，重标定常数并重写所有受影响的文档
- `docs/04-eval-protocol.md` §3.3 已写入"真实 tok/s < 预测 50% 即证伪"的条件
