# ADR 0002 · 层间注意力路由不省显存，只省速度且收益 < 1%

- 状态：已接受（负面结论）
- 日期：2026-11-16
- 相关：`docs/01-introduction.md` §6.2、`docs/03-roadmap.md` §2.4

## 背景

阶段二原计划做"可学习的层间注意力路由"，假设它能通过减少全局注意力层来省 KV 缓存。这个假设在 `docs/01-introduction.md` 的初稿里写成：

> 收益：平均全局层数可能从 1/6 降到 1/10，KV 缓存对应减少。

## 决策

**删除该假设。** 该改动只有速度收益（< 1%），没有显存收益。

## 依据（实测）

用预算模型扫 `global_every`：

| `global_every` | 全局层数 | `kv_gib`（分配） | `kv_decode_gib`（每 token 读） |
|---:|---:|---:|---:|
| 6（当前） | 4 | **0.810** | 0.210 |
| 10 | 2 | **0.810** | 0.160 |
| 26（全局部） | 0 | **0.810** | 0.130 |

**`kv_gib` 完全不变。**

原因：KV 缓存必须为每一层预留全量空间，因为训练/推理时任何层都可能被路由为全局层。分配是静态的，路由是动态的 —— 动态的东西不能决定静态分配。

## 收益重算

就算路由完美到 0 个全局层：

```
kv_decode 0.210 -> 0.130 GiB
总读取     5.48 GiB（权重主导）
提速上限   0.08 / 5.48 = 1.5%
```

再考虑路由本身的开销（每层一个 hidden→2 的投影 + 分支），**净收益接近 0**。

## 修正后的定位

- 阶段二 2.4 从 P1 降到 P3
- 文档里所有"KV 缓存减少"的表述改为"仅解码读取量下降"
- 只有在 32k+ 上下文（KV 读取变成主导项）时才重新评估

## 教训

**这个错误来自"局部正确"的推理**：全局层只存窗口、局部层存全量，听起来前者更省。但混淆了"每层存多少"与"总共分配多少"。

**防再犯的机制**：已在 `tests/test_budget_model.py` 加了 `test_windowed_decode_reads_less_than_full_kv` 与 `test_full_attention_reads_all_kv`，锁定"分配量不随 window 变"这个行为。任何人改动模型逻辑导致这两个测试失败，都会立刻暴露。
